# 架构决策记录

> 状态：持续更新
>

>
> 本文档按【时间 · 意图 · 背景情况】三维结构，按时间顺序记录本项目的架构决策。
>
> 依据：项目规则「修改架构必须记录设计决策」。
>
> 记录原则：
>
> 1. 只记录会影响后续实现的决策，不记录日常实现细节；
> 2. 每条决策必须写明**触发它的背景**，否则后人无法判断该决策是否仍然成立；
> 3. 决策被推翻时不删除原条目，追加新条目说明推翻原因。

## D-001

| 维度 | 内容 |
| ---- | ---- |
| **时间** | 2026-09-22 |
| **意图** | 采用 L1 RawSource → L2 Facts → L3 Domain Objects → L4 Report IR 四层模型，禁止建立同时包含原始数据、事实、工程对象与报告内容的「大统一模型」 |
| **背景** | 项目存在多源异构输入（文字、Excel、图片、规范、模板），如果直接抽取成领域对象，会同时丢失原始定位（不可追溯）与表达自由（模板耦合）。分层是为了让「是什么」与「怎么写」在不同层各自演化 |
| **影响** | `03_CANONICAL_DATA_MODEL.md`、`04_REPORT_IR.md` |
| **是否仍然成立** | 是。v0.2 复核未发现该模型的结构性问题 |

## D-008

| 维度 | 内容 |
| ---- | ---- |
| **时间** | 2026-09-22 |
| **意图** | Fact 数值存储由「SI 基准 + 原始单位」改为「**原始值 + 原始单位 + quantity_kind（量纲种类）**」。单位换算只发生在计算步骤内；显示一律使用原始单位与原始精度 |
| **背景** | 架构评审指出 SI 存储对工程报告是负优化：报告永远按原始单位呈现（kN、mm、MPa），显示时全部要换算回来，换算链引入舍入误差；`32400000` 这类浮点值在 diff 与回归中制造无意义噪音。经复核成立。**补充**：仅存原始单位会丢失量纲一致性检查能力（mm 被当成 m 相加无法被发现），因此必须同时存 quantity_kind |
| **影响** | `03_CANONICAL_DATA_MODEL.md` §8 / §10；`05_EVALUATION.md` §6.1 |
| **是否仍然成立** | 否，原 v0.1 设计作废 |
| **发起人** | 架构评审 + 架构自查补强 |

## D-012

| ---- | ---- |
| **时间** | 2026-09-22 |
| **意图** | Evaluation Case 分三级（gold / silver / bronze）；Ground Truth 的事实值必须从原始输入资料独立推导，禁止抄录报告正文；逆向链路与生成链路分离，逆向产物冻结为 JSON 固件；历史报告中的已知错误登记为 known_issues |

## D-017

| 维度 | 内容 |
| ---- | ---- |
| **时间** | 2026-09-22 |
