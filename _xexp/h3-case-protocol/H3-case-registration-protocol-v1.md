## 1. 正式判定的六个使用条件（U1–U6）

**U1 来源存在且适用范围一致**
该约束的证据来源必须**实际存在**于目标基线（或以显式「缺失/待补」声明登记），
且该约束的适用范围必须与**目标基线 commit/tree** 及**拟设计案例的适用范围**一致。

**U2 `expected_invariant` 必须能够明确判定**
不变量须**无歧义、可判定**（可被测试或人工按明确步骤核验）。
含"尽量/合理/适当"等不可判定措辞者，判不满足。

**U3 `severity` 必须已经确定**
`severity` ∈ {`high`, `normal`}。取值为 `PENDING` 者**不满足**（不得用于任何严重度判定）。

**U4 支持标准答案的关键证据必须实际存在**
须有**至少一条**可在基线内解析的证据（代码位置 / 契约条文 / 测试结果）。
**仅有函数名、命名模式或代码注释，不足以满足 U4。**
（例：某函数名含 `validate` 不构成证据；须给出其不变量所在条文与可核验位置。）

**U5 契约来源或约束适用性未确认的条目，即使 `severity=high` 也不得直接用作正式标准答案依据**
具体判据：`change_control = PENDING`（即契约来源或管制状态未确认）→ **不满足 U5**，
无论其 `severity` 为何值。

**U6 「条目属于高严重度」与「证据已足以支持正式使用」是两件事**
- **性质**：`severity = high` 描述**后果严重度**（由 `impact_rationale` 证成）。
- **授权**：**可用** = U1 ∧ U2 ∧ U3 ∧ U4 ∧ U5 **全部满足**。
- 因此：`severity=high` **不蕴含**可用；`severity=normal` **也不蕴含**不可用。
- **禁止**由 `severity=high` 直接推出"可用于正式标准答案"，亦禁止由
  `HIGH_RISK_CONTRACT_FUNCS` 名字匹配推出任何严重度或可用性。

> **U6 是本次新增的关键约束**：它把 H3-01R 暴露的偏差（"名字/规则命中即当作高风险依据"）
> 从制度上封堵——性质与授权分离，且授权需独立证据。

## 3. 待决条目逐项限制（含与既有约定的冲突核对）

| 条目 | 限制 | 与 v1.2.1 M-6 的关系 | 与 Manifest v4 §6 的关系 |

| `TZ-001` | 同上（§5.1 条文缺失）；补充：**即使其 `severity=high` 且后果依据充分，仍不得使用**（U5/U6） | 无冲突（同 AU-001） | 一致（v4 §6 同款表述） |
| `FZ-001` | **两轴均待决** → 既不得用于判 `ALARM_HIGH`，也不得用于判 `ALARM`；须先确定 severity 与契约状态 | 无冲突：M-6 只管 `severity=PENDING` 不得判 `ALARM_HIGH`；U3 进一步禁止用于任何严重度判定 | 一致（v4 §6:"两轴均待决；不得用于任何 severity 判定"） |
| `DS-001` | 禁止用于正式判定（`change_control` 待决 → U5 不通过）；其 `severity=normal` 已定，但**不足以**授权使用 | 无冲突（M-6 未涉及 normal 的授权；U5 为新增授权门槛） | 一致（v4 §6:"`change_control` 待决"） |
| `PERM-000` | 类别级待决：基线无该类实现 → **无可登记条目**；若 H3 需覆盖该类别，须以**注入式案例**另行声明约束来源并经人工审查 | 无冲突 | 一致（v4 §6 同款表述） |

不改变 M-6 的判定读取规则。**
